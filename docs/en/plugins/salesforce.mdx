Discover accounts, query Salesforce, and report pipeline evidence from the selected organization.

<Badge text="Sales" variant="tip" /> <Badge text="Integrated" variant="note" />

## Requirements

- xcsh 22.4.6 or later.
- Salesforce command-line interface (CLI), `sf`.
- An authenticated default organization with API access.
- The intended [My Domain login URL](#set-up-a-login-domain), if your organization requires one.

## Install

```bash
xcsh plugin install salesforce@f5-sales-demo-marketplace
```

Check readiness and complete [integration setup](/marketplace/en/getting-started/#complete-setup) if required.

## Inspect an organization and query pipeline

Ask `sf_org_display` to confirm the intended organization, then use `sf_describe` to discover the opportunity fields you need. Request a bounded `sf_query` or `sf_pipeline_report`, such as open opportunities grouped by close quarter.

| Task | Native tool |
| --- | --- |
| Inspect the selected organization | `sf_org_display` |
| Discover real fields and relationships | `sf_describe` |
| Query records with Salesforce Object Query Language (SOQL) | `sf_query` |
| Build a pipeline report | `sf_pipeline_report` |
| Inspect command usage or execute an explicit command | `sf_help`, `sf_exec` |

Discover fields before querying custom objects. `sf_describe` matches API names
and labels, returns active picklist values, and identifies child relationships.
Ask for open opportunities grouped by close quarter or for account-team coverage
in ordinary language.

## Check the result

Check integration status and use `sf_org_display` to confirm the intended
organization. Run a bounded query and compare the report with its source records.

## Set up a login domain

Setup reviews `SF_ORG_INSTANCE_URL` first, then the CLI's `org-instance-url`
configuration, and otherwise uses `https://login.salesforce.com`. It normalizes
Lightning URLs to My Domain login URLs and shows the effective `--instance-url`
before authentication. Set the intended value through protected local
configuration before setup. A changed login URL requires a new review.

Setup reuses a working host CLI. Missing CLI installation follows the reviewed
host-specific route. Authentication runs from human setup, rather than a
model-callable tool.
