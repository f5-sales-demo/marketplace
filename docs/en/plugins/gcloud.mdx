<Badge text="Cloud" variant="tip" /> <Badge text="Integrated" variant="note" />

## Requirements

- Google Cloud CLI, `gcloud`.
- An authenticated account and the intended active configuration and project.

## Install

```bash
xcsh plugin install gcloud@f5-sales-demo-marketplace
```

Check readiness and complete [integration setup](/marketplace/en/getting-started/#complete-setup) if required.

## Inspect the active project

Use `gcloud_config_list` to confirm the active account, configuration, and project. Ask `gcloud_compute_instances_list` or `gcloud_storage_buckets_list` for that project, then compare returned resources with the requested scope.

| Task | Native tool |
| --- | --- |
| Inspect active configuration | `gcloud_config_list` |
| List projects | `gcloud_projects_list` |
| List compute instances | `gcloud_compute_instances_list` |
| List storage buckets | `gcloud_storage_buckets_list` |
| Inspect command usage or execute an explicit command | `gcloud_help`, `gcloud_exec` |

If credentials expire, repeat human setup and reconfirm the active project before continuing.

observes F5 image/license identities and cloud prerequisites, and `gcp_ce_plan`
validates topology and sizing with a hashed readiness plan. Native is the default;
an explicit Terraform choice must match the intent.

Apply, upgrade, failover and teardown tools report these gaps before mutation.
Inventory, status and diagnostics observe cloud provisioning; registration,
physical interface identity, platform health, routing and application traffic
remain separate unknown gates. Deployment labels alone cannot authorize deletion.

Disposable native and shared Terraform runner qualification also observed matching
node global health after initial software and OS convergence, followed by owned
cleanup and independent absence checks. These campaign results do not establish
