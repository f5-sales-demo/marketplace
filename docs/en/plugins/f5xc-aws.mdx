Inspect Amazon Web Services resources and plan F5 Distributed Cloud Customer Edge deployments.

<Badge text="Development" variant="tip" /> <Badge text="Integrated" variant="note" />

Plugin identifier: `aws`. [Source and release metadata](https://github.com/f5-sales-demo/marketplace/tree/main/plugins/aws/.xcsh-plugin/plugin.json).

## Prerequisites

Follow [Get started](/marketplace/en/getting-started/) for shared installation
requirements. Allow about 5 minutes for an initial check after setup.

- Amazon Web Services (AWS) CLI with the required compute, quota, and networking commands.
- Credentials or an authenticated single sign-on (SSO) profile for the intended account and partition.
- The Platform plugin with F5 Distributed Cloud authentication.
- An authorized target and an accepted F5 Marketplace subscription.

Plugin dependencies: [F5 Distributed Cloud Platform](/marketplace/en/plugins/f5xc-platform/).

## Set up

Install from your shell after registering the marketplace:

```bash
xcsh plugin install aws@f5-sales-demo-marketplace
```

Check readiness. If setup is required, run the human setup flow in an
interactive terminal:

```bash
xcsh plugin status aws
xcsh plugin setup aws
```

## Use the plugin

| Task | Native tool |
| --- | --- |
| Inspect identity, storage, or instances | `aws_sts_whoami`, `aws_s3_ls`, `aws_ec2_describe_instances` |
| Discover eligible regions, images, and compute | `aws_compute_discover` |
| Create an immutable plan, then apply or resume it | `aws_ce_plan`, `aws_ce_apply` |
| Inspect state, diagnose paths, or analyze boot | `aws_ce_status`, `aws_ce_diagnose`, `aws_cloud_init_analyze` |
| Inspect command usage or run an explicit command | `aws_help`, `aws_exec` |

Customer Edge (CE) requests first verify identity, current F5/AWS sources,
the shared automation contract, and `f5xc_ce_v2_capabilities`. Discovery enumerates
regions, resolves exact images, and checks agreements, quotas, zones, interfaces,
policy, and existing network state. Apply revalidates the saved plan and source
digests; account or cloud-state drift requires a fresh plan.

| Network profile | Routing model |
| --- | --- |
| `direct-eni` | Explicit routes to the single-node inside interface |
| `nlb-ingress` | Network Load Balancer (NLB) ingress with explicit target and health checks |
| `tgw-static` | Transit Gateway (TGW) attachments and explicit route tables |
| `tgw-connect` | Capability-gated Generic Routing Encapsulation (GRE) and Border Gateway Protocol (BGP) peers |

The NLB isn't a routed next hop. Three-node NLB and TGW profiles require design
and live acceptance evidence. Enable TGW Connect only when current F5 guidance
and the authenticated tenant advertise the exact supported schema.

Plans list billable resources, ownership tags, rollback state, and the plan hash.
Lifecycle operations include deploy, reconcile, start, stop, resize,
update-network, replace-node, repair, and teardown. Three-node changes advance
one node at a time through compute, registration, health, and routing gates.
Single-node disruption requires a maintenance window.

Headless mutation requires `XCSH_CE_HEADLESS_MUTATIONS=1` and the exact plan
hash; destruction also requires `XCSH_CE_ALLOW_DESTROY=1`. Initial Marketplace
legal acceptance stays in the AWS console. Bootstrap uses a one-use Platform
reference and a temporary restricted file; tokens never enter plans or reports.
See the [shared CE contract validation](https://github.com/f5-sales-demo/marketplace/blob/main/plugins/platform/src/ce/release-contract.ts)
for the current contract and lifecycle gates.

## Verify

Use `aws_ce_status`, `f5xc_ce_v2_status`, and passive `aws_ce_diagnose`.
Check instance and interface ownership, registration, health, target/peer state,
routes, and traffic. Automated checks alone don't establish live topology support.

## Clean up

Approve a teardown plan that restores brownfield routing before deleting
exactly owned resources. Confirm AWS and F5 absence, then inspect for remaining
billable resources.

For plugin removal, follow
[Remove a plugin](/marketplace/en/getting-started/#remove-a-plugin).
