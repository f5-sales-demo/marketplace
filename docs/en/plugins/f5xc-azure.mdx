Inspect Azure resources and plan F5 Distributed Cloud Customer Edge deployments.

<Badge text="Cloud" variant="tip" /> <Badge text="Integrated" variant="note" />

## Requirements

- Azure CLI, `az`, authenticated to the intended AzureCloud subscription.
- The Platform plugin with F5 Distributed Cloud authentication.
- An authorized lab or demo target.

## Install

```bash
xcsh plugin install azure@f5-sales-demo-marketplace
```

Check readiness and complete [integration setup](/marketplace/en/getting-started/#complete-setup) if required.

## Inspect resources and plan a site

Confirm the subscription with `az_account_show` and inspect resources with `az_resource_list` or `azure_ce_inventory`. Run `azure_compute_discover`, then request an `azure_ce_plan`. Review exact images, node count, cost, ownership, and routing before apply.

| Task | Native tool |
| --- | --- |
| Inspect account, groups, resources, or virtual machines | `az_account_show`, `az_group_list`, `az_resource_list`, `az_vm_list` |
| Query Resource Graph or activity history | `az_resource_graph_query`, `az_activity_log_list` |
| Correlate Customer Edge inventory | `azure_ce_inventory` |
| Discover eligible compute and images | `azure_compute_discover` |
| Create an immutable plan, then apply it | `azure_ce_plan`, `azure_ce_apply` |
| Inspect site state or diagnose boot and routing | `azure_ce_status`, `azure_ce_diagnose`, `azure_cloud_init_analyze` |
| Inspect command usage or run an explicit command | `az_help`, `az_exec` |

Customer Edge (CE) work starts with current official F5 and Microsoft guidance,
the shared automation contract, tenant capabilities, and live catalog evidence.
Discovery records source digests and exact image versions. Plans fail closed
when the research receipt or cloud observations are missing or stale.

One-node plans use explicit routes through the data-plane address. Eligible
three-node plans use symmetric nodes and Azure Route Server peers. Discovery
checks compute capacity, interfaces, zones, quotas, policy, and Marketplace terms.
Brownfield plans record the exact routing state to restore at teardown.

`az_vm_list` separates optional power state from default-hidden network
identifiers. Resource Graph's Kusto Query Language (KQL) query is passed with
`--graph-query`; the global `--query` option projects the result with JMESPath.

Headless mutation requires `XCSH_CE_HEADLESS_MUTATIONS=1` and the exact plan
hash. Terms acceptance also requires `XCSH_CE_ACCEPT_MARKETPLACE_TERMS=1`;
destruction requires `XCSH_CE_ALLOW_DESTROY=1`. Bootstrap material travels through
a one-use Platform reference, outside plans and reports. Retired Azure-specific
compatibility variables and schema-v1 plans aren't supported.

## Check the result

Use `azure_ce_status`, `f5xc_ce_v2_status`, and passive
`azure_ce_diagnose`. Confirm node count, registration, health, peer state,
effective routes, and the checkpoint against the approved plan.

## Finish the task

Create and approve a `teardown` plan. Confirm that routing is drained,
recorded brownfield associations are restored, and only owned Azure and F5
resources are removed.
