Find the repository that owns a documentation change, then author and preview the content.

<Badge text="Productivity" variant="tip" /> <Badge text="Content" variant="note" />

Plugin identifier: `docs-pipeline`. [Source and release metadata](https://github.com/f5-sales-demo/marketplace/tree/main/plugins/docs-pipeline/.xcsh-plugin/plugin.json).

## Prerequisites

Follow [Get started](/marketplace/en/getting-started/) for shared installation
requirements. Allow about 5 minutes for an initial check after setup.

- A documentation repository in the F5 sales-demo fleet.
- Docker for the local preview workflow.

## Set up

Install from your shell after registering the marketplace:

```bash
xcsh plugin install docs-pipeline@f5-sales-demo-marketplace
```

This content plugin has no integration setup or authentication step. Start a
fresh xcsh session to load its skills and commands.

## Use the plugin

Use `pipeline-navigator` to locate configuration ownership across
`docs-control`, `docs-theme`, `docs-builder`, and `docs-icons`. It also explains
the release dispatch chain and managed-file reconciliation.

Use `content-author` for page structure and MDX conventions. Run
`/docs-pipeline:preview-docs` for a local container preview, or
`/docs-pipeline:docs-pipeline-status` to inspect pipeline readiness.

## Verify

Build the changed content and open its rendered pages. For publication,
confirm that the deployment used the intended content commit.

## Clean up

Stop the preview container you started. Preserve authored files and review
evidence; remove only disposable preview output.

For plugin removal, follow
[Remove a plugin](/marketplace/en/getting-started/#remove-a-plugin).
