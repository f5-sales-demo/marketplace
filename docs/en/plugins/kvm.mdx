Deploy a dual-interface Secure Mesh Site v2 with a private origin and an inside virtual IP on a wired LAN.

<Badge text="Cloud" variant="tip" /> <Badge text="Integrated" variant="note" />

## Requirements

- Ubuntu 24.04 x86_64 with Kernel-based Virtual Machine (KVM), libvirt, and QEMU access.
- Terraform, `curl`, and the Platform integration.
- Capacity for an 8-vCPU, 32-GiB-memory, 100-GiB-disk Customer Edge.
- A supported wired local area network (LAN), two distinct reserved candidate addresses, and an application namespace.

## Install

```bash
xcsh plugin install kvm@f5-sales-demo-marketplace
```

Check readiness and complete [integration setup](/marketplace/en/getting-started/#complete-setup) if required.

## Check host and network readiness

Ask `kvm_smsv2_readiness` to inspect the intended host, wired LAN, available capacity, reserved addresses, and application namespace. Request a plan through `kvm_smsv2_deploy`; review bridge ownership and rollback checkpoints before host preparation or deployment.

| Task | Native tool |
| --- | --- |
| Inspect host and network readiness | `kvm_smsv2_readiness` |
| Plan or apply the owned deployment | `kvm_smsv2_deploy` |
| Inspect site, interfaces, and workload | `kvm_smsv2_status` |
| Reconcile against a reviewed plan | `kvm_smsv2_reconcile` |
| Remove the owned deployment | `kvm_smsv2_destroy` |

The site-local outside (SLO) interface uses an isolated libvirt network. The
site-local inside (SLI) interface joins the wired LAN through an owned bridge.
An inside virtual IP (VIP) exposes one Hypertext Transfer Protocol (HTTP) load
balancer to LAN clients; its origin remains isolated. The on-link VIP needs no
Border Gateway Protocol (BGP) peer.

Site and registration objects stay in `system`. Application objects use
`applicationNamespace` or the active context's `XCSH_NAMESPACE`. The chosen
namespace persists with the deployment; changing it requires an owned teardown
and fresh deployment.

Host preparation records network ownership and uses rollback checkpoints.
Occupied bridges, unsupported LAN ranges, address conflicts, and conflicting
receipts block the operation. Address probing doesn't reserve an address in
the router's Dynamic Host Configuration Protocol (DHCP) pool. Inspect the
[network contract](https://github.com/f5-sales-demo/marketplace/blob/main/plugins/kvm/NETWORKING.md)
before approving host changes.

## Check the result

Confirm registration, the observed SLO/SLI interface mapping, origin isolation,
and a zero-change reapply. Test VIP Address Resolution Protocol (ARP) and HTTP
from another LAN device. Host-only probes don't complete external-device acceptance.

## Finish the task

Use `kvm_smsv2_destroy` with the reviewed saved plan. Verify owned virtual
machines, networks, site objects, and application objects are absent. Check
that the management network is restored and unrelated resources remain.
