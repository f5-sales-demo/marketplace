## Requirements

- xcsh 21.38.1 or later for provenance-aware maps.
- Python 3.9 or later, `curl`, `jq`, and access to the selected live sources.
- Optional `ping`, `tracepath` or `traceroute`, and `mtr` for path diagnostics.

## Install

```bash
xcsh plugin install cloudstatus@f5-sales-demo-marketplace
```

Evidence is collected when invoked; no account setup or background polling is required.

## Check current incidents

Run `/cloud-status incidents`, or ask: “Show a current map of Canadian F5 Regional Edges with coordinate provenance.” Review source timestamps, partial results, and unresolved locations before drawing conclusions.

| Task | Entry point |
| --- | --- |
| Check incidents, maintenance, or components | `/cloud-status` and the `monitor` skill |
| Locate F5 Regional Edges or request a map | Ordinary language and the `location` skill |
| Investigate registration, routes, peering, or paths | Ordinary language and `network-intelligence` |

Domain Name System (DNS), Registration Data Access Protocol (RDAP), Border
Gateway Protocol (BGP), and Resource Public Key Infrastructure (RPKI) evidence
answer different questions. Reports separate observed facts, correlations,
inference, and unresolved candidates.

Regional Edge work uses the registry-only location collector with F5 Statuspage,
PeeringDB, and Wikidata. Maps use validated coordinates; unresolved locations
stay unplotted. General network work has a wider source ladder. A facility match
doesn't establish that a particular F5 service runs in that building.

Path troubleshooting uses four ping packets, a trace of at most 30 hops, five
`mtr` cycles, and a 45-second total limit. Missing tools and blocked probes
remain reported limitations. `STATUSPAGE_URL` selects another Statuspage-backed
service for monitoring; F5 location work keeps its F5 sources.

## Check the result

Check observation timestamps and cited sources. Preserve partial results
and errors when a source is unavailable. Confirm map coordinates have provenance.
