Install a marketplace plugin and check that it is ready for your task. Allow
about 5 minutes for a content plugin; account or desktop setup takes longer.

## Prerequisites

- A current xcsh installation with plugin lifecycle support.
- Git and HTTPS access to the marketplace repository and release sources.
- An interactive terminal for human setup.
- The selected plugin's account, tool, host, and permission requirements.

The [plugin catalog](/marketplace/en/plugins/) links those requirements.
Run shell commands below in your terminal. Run slash commands inside an
interactive xcsh session.

## Register the marketplace

```bash
xcsh plugin marketplace add f5-sales-demo/marketplace
xcsh plugin marketplace list
```

Confirm that `f5-sales-demo-marketplace` is enabled. Register the source once
for the intended user environment.

## Install a plugin

Start with Documentation tools:

```bash
xcsh plugin install docs-tools@f5-sales-demo-marketplace
```

Use the catalog's identifier for another plugin. To inspect the dependency
plan without installing:

```bash
xcsh plugin install zoom@f5-sales-demo-marketplace --dry-run --json
```

Add `--scope project` when you need a project-scoped installation. The default
scope is `user`. Review dependencies and any direct-install setup before it runs.

## Complete setup

Content plugins need no integration setup. For integrated plugins, inspect
readiness and follow their page's instructions. For example:

```bash
xcsh plugin status salesforce
xcsh plugin setup salesforce
```

Setup is human-only and doesn't accept `--json`. It reviews the exact plan
before installation or authentication. Keep credentials in provider-managed
storage or protected configuration.

Platform opens a context wizard inside the xcsh terminal user interface:

```text
/plugin setup platform
```

Dependency installation and upgrades may leave an integration requiring setup.
Run the plugin's human setup flow when needed.

## Verify

Start a fresh xcsh session after installation or upgrade. Check installed plugins:

```bash
xcsh plugin list
```

For Documentation tools, open a repository with Markdown with JSX (MDX) pages
and run:

```text
/docs-tools:review-mdx
```

Confirm that the review reports the intended files. For integrated plugins,
use `xcsh plugin status <PLUGIN_IDENTIFIER>` and the plugin page's verification
steps. Content-only plugins have no integration status entry.

## Update a plugin

Refresh the marketplace catalog, then upgrade the installed plugin:

```bash
xcsh plugin marketplace update f5-sales-demo-marketplace
xcsh plugin upgrade docs-tools@f5-sales-demo-marketplace
```

Start a fresh session and repeat verification. Review release notes before
upgrading a plugin that manages persisted plans or receipts.

## Clean up

Finish the plugin's resource cleanup before removing its files. Uninstalling
doesn't destroy cloud resources, stop existing sessions, or revoke provider credentials.

### Remove a plugin

```bash
xcsh plugin uninstall docs-tools@f5-sales-demo-marketplace
```

Use the same `--scope project` if you installed into project scope. Remove the
marketplace registration only when you no longer need it:

```bash
xcsh plugin marketplace remove f5-sales-demo-marketplace
```

## Troubleshoot readiness

| Symptom | Next step |
| --- | --- |
| Marketplace is missing | Register it again and check `marketplace list`. |
| Plugin files are installed but tools are missing | Start a fresh session and check `plugin list`. |
| Integration reports `setup_required` | Follow its human setup flow and resolve the reported requirement. |
| Status says no integration is registered | Check the identifier, installation, and enabled state; content plugins have no integration. |
| Account or project differs from the target | Select the intended context before proceeding. |

See [Reference](/marketplace/en/reference/) for manifest and readiness details.
