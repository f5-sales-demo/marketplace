# GCP original xcsh reader closure source qualification

Issue: #1559. Draft PR: #1698. Engineering acceptance remains incomplete.

The original native xcsh creation reader now retains immutable request,
admission, prepared scope and final capture bindings. A source-issued collector
independently verifies native bootstrap, submitted arguments, parent identity,
plan and provider hashes, completion and physical process group absence.
It can retain closure evidence after reader failure while failed capture
results and unresolved locks remain unchanged.

Copied readers and explicit offline executor seams cannot issue native closure
evidence. Durable source sets retain exact ownership and attempt coverage.
Changed source identity, including same-byte file replacement, refuses.
Existing generic receipts and the distinct guest origin keep their semantics.

The failing-first pair failed because the collector was absent, then passed
after implementation. The real native regression deliberately supplies an
invalid offline Terraform input to the shipped Python reader. It verifies
process closure after failure and performs no provider or cloud operation.
It does not prove successful GCP capture, deployment, registration or traffic.

Validation passed on Ubuntu with Bun 1.4.4: 72 affected cases and 1,465
assertions across seven files; final source/runtime checks cover 59 cases and
503 assertions across three files. All three full strict plugin typechecks,
warning-strict configured lint, the normal three-plugin build and generated
catalog verification pass. Independent review verifies 113 retained files,
four native group absences and three immutable xcsh source admissions.

Candidate versions are GCloud 1.7.70, Platform 6.3.33 and Terraform 2.4.163.
These are source-qualified candidates; publication and installed acceptance
remain open. Independent SSH/access/client closures, early startup failure paths,
complete factory coverage, provider renewal across expiry, installed runtime,
live lifecycle and networking, CI, review, publication and installed artifact
acceptance remain required.
