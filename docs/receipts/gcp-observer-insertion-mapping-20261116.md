# Original observer insertion and VM evidence

Issue: [marketplace #1559](https://github.com/f5-sales-demo/marketplace/issues/1559).
PR: [#1698](https://github.com/f5-sales-demo/marketplace/pull/1698), retained as draft.

Terraform 2.4.122 binds observer insertion to the original plan, immutable
21-resource baseline, versioned intent, original provider response and
factory-issued pinned-image reader. The observer has separate VM, disk,
metadata, labels and network rules. CE bootstrap and forwarding rules are
not reused for the observer.

Independent VM and disk observations join the insertion operation, numeric
identities, absence chronology, image ID, external disk ownership and single
SLI interface. Serial capture brackets current ownership. Copied sources,
changed resources, stale evidence and copied final callbacks refuse; rejected
packets remain retired after restoration. These APIs grant no execution,
insertion or live qualification.

GCloud 1.7.55 also fixes the observer compiler's request-reason binding.
The original version 2 intent is validated before deriving the internal
CE-only version 1 fingerprint. The original intent, reason string and stored
receipts are preserved.

Failing-first evidence retains missing APIs, the compiler defect, a copied
image-reader acceptance and missing compiled exports. Additional checks cover
VM/disk replacement during serial capture, stale observations, metadata drift
and the actual final callback. Actual issuers drive the fixtures; HTTP and
serial observations remain explicitly offline. No cloud submission occurred.

Verification passed: 730 Terraform tests, 826 combined Platform/GCloud tests,
141 shared regressions, 20 compiled bridge checks, all three strict typechecks
and runtime bundles, catalog/tracker, agent validation and staged privacy.
Missing validation dependencies and a missing published-package selector were
retained and repaired before the affected checks passed. Normal commit hooks
and new-head CI are separate delivery gates.

Built-in capture factory composition, real provider token refresh, guest
capture and every original live networking/lifecycle/traffic/recovery/cleanup/
restoration gate remain required. Ordinary installed runtime, review, merge,
publication, verified downloads and published user-scope installation also
remain open. Historical failures, locks, frozen collectors and immutable
v12.3.1 assets are preserved.
