## Implementation and tests

The checker binds the original execution, configuration, saved plan, Terraform and Google provider
executables, ADC bytes, principal, audience and provider PID/group/boot/birth identity. Both
independent token observations must use bounded HTTP clocks, distinct token and response hashes, and
the same principal and audience. The second request must start at least one second after the
conservative upper bound on original token expiry. Fresh original-provider observations must bracket
both reads; changed identities, clock jumps and observations beyond the immutable two-hour deadline
refuse.

Its result explicitly requires independent review and grants no cloud execution. It checks evidence
consistency; the trusted reviewer must still verify original HTTPS framing/bodies and kernel process
records. The existing ADC admission and its live-refresh hold remain unchanged.

Failing-first evidence tests retained the missing implementation failure. Twenty focused tests and
26 assertions pass. Deadline and provider-package regressions bring the selected shared run to 30
tests and 65 assertions. Seven fixture-guard tests pass after a retained wrong-Terraform-version
failure. The initial shared run used an aliased Mac temporary path and correctly refused
provider-package inspection; the distinct run with `TMPDIR=/private/tmp` passed. Source typecheck
passes.

The runtime build passed with unchanged generated bytes. Terraform's manifest, package and generated
catalog agree on 2.4.5. Repository hooks passed using the existing Node 22 executable after the
default Node executable aborted two Markdown hooks; both executable hashes and the failure are
retained privately. Markdown CLI2, spelling, staged secret detection and both staged PII modes passed.

## Provider mapping and actual saved plan

The pinned [Google 8.7.0 client-config
implementation](https://github.com/hashicorp/terraform-provider-google/blob/v8.7.0/google/services/resourcemanager/data_source_google_client_config.go)
calls the configured provider token source and marks its access token sensitive. The [matching
data-source
documentation](https://github.com/hashicorp/terraform-provider-google/blob/v8.7.0/website/docs/d/client_config.html.markdown)
confirms sensitive state retention. This permits a future before/after token experiment without
provisioning GCP resources.

The private fixture declares Terraform 1.16.6, Google 8.7.0 and the frozen XCsh 15.13.0 dependency.
It contains two built-in local `terraform_data` objects and two deferred Google client-config reads.
Both token outputs are sensitive. The first readonly initialization refused because XCsh was present
in the frozen lock but absent from the declaration. That execution and its natural closure remain
preserved. A distinct successor declared the same pinned dependency and passed initialization,
validation, saved planning and plan inspection.

An independent guard verified the actual four-change plan: two local creates and two token data
reads, with zero cloud resources and sensitive outputs. The actual transport retained four
independently reviewed natural execution closures. It explicitly refuses apply; the saved plan is
preparation evidence and cannot be replayed as an authorization.
