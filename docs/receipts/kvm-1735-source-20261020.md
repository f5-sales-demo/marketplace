# KVM 3.2.1 source presentation verification

Campaign [1579](https://github.com/f5-sales-demo/marketplace/issues/1579),
child [1595](https://github.com/f5-sales-demo/marketplace/issues/1595),
implementation [1735](https://github.com/f5-sales-demo/marketplace/issues/1735).

The five native tools now declare exact controller commands using the same argument
builder as execution. Readiness shows setup state, consequential checks and capacity
units. Status shows acceptance, traffic counts, named VM states and identity evidence.
Removal shows remaining owned counts and bridge restoration. Partial results remain
pending. Selected summaries retain zero, false, empty strings and explicit unknowns;
complete safe details and original operator guidance remain available on expansion.

The installed 3.2.0 module-adapter baseline used a synthetic readiness result against
published runtime 23.9.5. It exposed a generic label and raw capacity keys. That baseline
is neither native dispatch nor live service evidence. Controller source inspection also
identified a name-to-state domain map and separate service active/enabled observations;
regressions now cover those real shapes.

## Source checks

Mac arm64 with Bun 1.4.2 and development runtime 23.9.5 passed:

- Eleven presentation regressions, including opaque text fallback, including harmless Bash and Zsh
  execution proving exact reconstruction of command arguments with quotes,
  substitutions as literal text, a newline and an empty string.
- Complete plugin suite: 22 Bun tests; 62 controller tests.
- Home-LAN suite: 43 tests; seven shell acceptance checks, including an isolated
  copied plugin cache and read-only readiness with temporary state.
- TypeScript typecheck, catalog validation, presentation ownership and tracker checks.
- Privacy enforcement and secrets checks against staged changes.

An isolated published minimum runtime 23.5.1 loaded all five tools, executed an
injected fixture controller for each tool and constructed ten nonempty result views.
Readiness/status/destroy receive empty parameters; deploy/reconcile preserve supplied
parameters. This lane establishes API loading and existing execution semantics.
It does not establish newer argv metadata, preview controls or runtime suppression
of automatic expanded evidence. Stable 23.9.5 remains the qualification target.

Initial failures are retained privately: the old development dependency lacked the
new presentation controls, real domain maps were omitted, enabled service failures
were lost, and partial results incorrectly implied completion. The broader catalog
suite also caught opaque text without details being replaced by `undefined`; a
focused regression and fallback repair retain the complete original text. Later broad checks
found stale 3.2.0 assertions and missing local PyYAML. Assertions are synchronized
with 3.2.1; fixtures use isolated PyYAML 6.0.3. No controller behavior changed.

## Remaining gates

Source tests do not establish published artifact, installed native matrix, model
workflow or supported-host service acceptance. Those gates require independent
receipts after delivery. Mutating tools use fixtures; deployment, reconciliation,
teardown and setup apply were not executed. Account-dependent gates remain deferred.

Tracker reconciliation reopens affected KVM and shared fingerprints conservatively,
retaining previous evidence and receipts. Salesforce rows and retired history remain
unchanged. No source-only result is promoted to installed or service VERIFIED.

Private evidence identifiers begin `kvm1735` and include red regressions, minimum
runtime checks, source suites, catalog, tracker, privacy and shell captures.
