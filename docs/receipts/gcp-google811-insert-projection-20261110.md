# Google 8.11 original insert projection

Issue: #1559. Delivery: draft PR #1698.

The Google 8.11 provider source identified by its authenticated binary constructs
instance insertion as a map-based POST to the exact project and zone. Its
transport adds the `alt=json` query parameter. The creation request includes
metadata, scheduling, advanced machine features and parameters. Service account
entries are emitted only when configured; an actual created VM still requires
independent proof that it has no service account.

Immutable upstream files are retained from commit
`67f96115b523ba050b11dad30237f14023667de8`. The authenticated binary records a
modified source tree; this evidence does not assume clean-tree equivalence or
replace an actual captured insertion.

Terraform plugin 2.4.73 now accepts the exact authenticated Google 8.11 profile
for original source-body projection. Body provenance, hashes, scoped identities,
ownership labels, bootstrap metadata and account rejection remain. Google 8.11
correspondence requires its own executable identity and the completed version-4
observation window. Historical Google 8.10 version-3/4 behavior remains unchanged.
No engine migration or stored receipt rewrite occurs.

Failing-first projection and correspondence cases exposed the former version
refusal. All 23 focused cases pass with 110 assertions, including exact 8.11
VM/audit joins and rejection of replaced numeric identities, copied references,
missing reasons, service accounts, missing bootstrap and wrong engines.

This change projects and corroborates source evidence. It grants no execution
authority: original insertion and apply qualification flags remain false. Fresh
managed VM insertion, original provider/RPC/audit/token/NIC/lifetime joins, full
default capture, actual expiry refresh, native/Terraform live behavior, ordinary
installed runtime and delivery gates remain required. Failed captures, historical
profiles, frozen collectors and immutable v12.3.1 remain preserved.
